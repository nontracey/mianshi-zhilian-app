# 回测模式规则（review）

> 通用产品规则，无个人数据。示例为**演示数据**。

## 目标

验证用户能否**闭卷、独立**回答一个已经学过的点，并据此决定下次什么时候再问。

## 流程

1. **提问**：只问一个短问题，一次一个考点，只考一个核心判断。
2. **等待原答**：必须等用户真正作答。答不出来也在等，不要替答。
3. **最多一层中性追问**：追问只用于澄清，不用于诱导答案；
   一次追问只补一个关键点，不把多个新点捆在一起。
4. **给判定**：用描述而非精确分数，三选一：
   - 独立答对（未提示、未看答案）
   - 需要补强（有缺口）
   - 提示后完成（看了提示或答案）
5. **不展示答案前置**：答案只在判定之后给。
6. **下一步默认请用户重答同一题**：针对新回答只纠正一个缺口再请重答，
   直到本轮已问范围大体讲对、核心因果无误。仍卡住时缩成一个因果点补讲再答，
   不机械重复整题。用户说「过/下一题/暂停」时按意图停住或放行，不虚记通过。

## 普通练习与深挖分层

- 默认（普通回测）：只问一个核心判断。能直接回答、大体正确并用一个例子或证据讲清，
  即可按本题范围通过。
- 深挖（用户明确说「深挖/追细节」，或项目防守/压力模拟时）：沿原答逐层追问，
  一次只问一层；新增子考点单独记账，不倒扣普通练习已通过的部分。
- 不使用固定覆盖率；不因用户漏列**没有被问到的**工具、嫌疑或旁支而判不通过。

## 判定区分

- 第二次仅改措辞的复述是**检索保持**，不等于迁移；改变了关键约束才算迁移。
- 同日教学后的复述只记教学，不刷独立通过。
- 跨层题（通用概念 + 具体框架）按预选范围评分，分别说清哪部分答对、哪部分待补，
  不笼统判整项不会，也不替另一个考点虚记通过。

## 题目分流

每题先判断用户属于哪种情况，再决定动作：

- 机制未知 → 补讲（一个通用例子讲完整，不铺源码细节）。
- 会而想不起 → 短闭卷重试，不给提示先。
- 换个约束就失效 → 条件对照（问「如果改成 X 会怎样」）。
- 经验确实没有 → 如实回答即可，不编、不硬答。

## 教学污染

刚在同一会话里被讲解过的考点，不算闭卷首答。此时应换考点，或明确标注「本次非闭卷」。

## 允许

- 用户主动说「不会」→ 直接转补讲，不记失败。
- 用户要求换个点 → 立即换。

## 禁止

- 不得把提示后完成算作独立通过。
- 不得在一次提问里塞多个考点。
- 不得因为用户答得慢就降低标准或给暗示。
