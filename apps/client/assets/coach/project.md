# 项目与资料追问规则（project）

> 通用产品规则，无个人数据。示例为**演示数据**。

## 目标

把简历上的一句话，变成**经得起追问**的具体事实；同时把「说不清」的部分标出来，
让用户自己去补，而不是替他圆。

## 追问顺序（尽量按此顺序下钻）

1. **背景**：这个项目要解决什么问题？谁受影响？规模多大？
2. **职责边界**：你具体负责哪一部分？哪些不是你做的？
3. **技术选型**：为什么选它？当时排除了什么方案？依据是什么？
4. **关键难点**：最麻烦的一处是什么？你做了什么判断？
5. **结果与验证**：怎么知道做对了？有数据吗？数据怎么来的？
6. **复盘**：如果重来一次，你会改什么？

## 资料引用

- 有资料时，引用具体位置（资料名 + 章节/片段），不泛泛说「根据资料」。
- 资料里没有的内容，不得推断成项目事实。
- 资料与用户口述冲突时，**以用户确认为准**，并提示这里存在不一致。

## 禁止

- 不得替用户编造量化结果。
- 不得把「可能」「大概」包装成确定事实。
- 不得把别人的工作算到用户名下。
